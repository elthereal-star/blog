Spring Boot 2 → 3

六项必须知道的变更 · 一次讲完

用 ← → 或空格翻页

01 / 07 · 为什么必须升

2.x 已经停止维护了

  • 2.7.x 是 2.x 的最后一个版本，其开源支持已于 2023 年 11 月结束
  • 新版 Spring Boot 3.x 才是当前主线，新特性只往这里加
  • 不升级的直接代价：拿不到安全补丁，出了漏洞只能自己兜
所以这不是「要不要升级」的问题，而是「什么时候升、怎么升得不那么痛」。
02 / 07 · Java 基线

最低 JDK 从 8 抬到了 17

Spring Boot 2.x
  • 最低 Java 8
  • 可跑在 11 / 17 上
  • 大量项目还停在 8
Spring Boot 3.x
  • 最低 Java 17
  • 推荐 Java 21（LTS）
  • 可用 record、sealed、虚拟线程
JDK 8 的项目必须先升 JDK，这一步绕不过去，也是升级路上最常见的第一个拦路虎。
03 / 07 · 命名空间（重点）

javax 变成了 jakarta

Spring Boot 2.x
  • javax.servlet.*
  • javax.persistence.*
  • javax.validation.*
Spring Boot 3.x
  • jakarta.servlet.*
  • jakarta.persistence.*
  • jakarta.validation.*
起因是 Oracle 把 Java EE 捐给了 Eclipse 基金会，改名 Jakarta EE，而 Oracle 不允许继续使用 javax 商标。

⚠️ 注意区分：javax.sql、javax.crypto 这些是 JDK 自带的，不用改；只有 Java EE 那一批才改。
04 / 07 · 框架内核

整条依赖链一起抬了版本

Spring Boot 2.x
  • Spring Framework 5.3
  • Hibernate 5
  • Tomcat 9
Spring Boot 3.x
  • Spring Framework 6.0
  • Hibernate 6
  • Tomcat 10 / Jetty 11
大量废弃 API 被真正移除，编译期就会报错。另外末尾斜杠匹配默认关闭了 —— /foo 不再匹配 /foo/。
05 / 07 · 自动配置注册

注册文件换地方了

Spring Boot 2.x
  • META-INF/spring.factories
  • 注解：@Configuration + 排序注解
Spring Boot 3.x
  • META-INF/spring/…AutoConfiguration.imports
  • 注解：@AutoConfiguration
只影响自己写 starter 的人。用现成依赖的话，升级依赖版本就行，不用手改。
06 / 07 · 原生镜像与可观测性

两块能力被收进核心

  • 原生镜像：2.x 要靠实验性的 Spring Native（已停止）；3.x 内置 AOT 编译，GraalVM 原生镜像成为一等公民，启动时间从秒级压到毫秒级
  • 可观测性：2.x 用 Spring Cloud Sleuth（已停止）；3.x 内置 Micrometer Observation + Micrometer Tracing
如果你的项目还在引 Sleuth，升级时要一并换成 Micrometer Tracing，这是容易被忽略的一处改动。
07 / 07 · 迁移清单

顺序别搞反

  • 先把项目升到 2.7（2.x 最后一版），把废弃 API 警告清干净
  • 再升 JDK 到 17 以上，确认编译和测试都过
  • 然后才动 Spring Boot 3.x，全局替换 javax.* → jakarta.*
  • 逐个确认第三方依赖有没有出 3.x 兼容版本
  • 最后重新验证配置项与安全配置 —— 很多属性名在 3.x 里被重命名了
