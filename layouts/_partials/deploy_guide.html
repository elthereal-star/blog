{{ partial "icon.html" "check-circle" }}本站已经在自动部署中

你正在看的这个站点就是结果：推送 {{ $branch }} 分支 → GitHub Actions 自动构建 → 发布到 GitHub Pages。 下面是完整复现步骤，换台电脑也能照着搭一遍。

1准备仓库

当前仓库：{{ $repoURL }}

  • 方案 A（推荐，个人主站）：仓库名填 {{ $user }}.github.io，上线后直接访问 https://{{ $user }}.github.io
  • 方案 B（项目子页面）：仓库名随意（现在是 {{ $slug }}），访问 https://{{ $user }}.github.io/{{ $slug }}/
2开启 Pages（关键一步）

进入仓库的 Settings → Pages，把 Build and deployment → Source 选成 GitHub Actions。

这一步漏了的话，Actions 会以 Get Pages site failed ... Not Found 失败，手动重跑一次即可。

3推送代码
git init
git add .
git commit -m "feat: init hugo blog"
git branch -M {{ $branch }}
git remote add origin {{ $repoURL }}.git
git push -u origin {{ $branch }}

推送后打开仓库的 Actions 标签页，可以看到构建在几十秒内跑完。

4本地预览与写文章
hugo new content posts/我的新文章.md
hugo server -D        # 本地预览 http://localhost:1313

写完直接 git push，1~2 分钟后线上就能看到。

{{ partial "icon.html" "shield" }}子路径部署最容易踩的坑

站点挂在 /{{ $slug }}/ 子路径下时，hugo.yaml 里的 baseURL、 以及 label.icon、assets.favicon* 这类资源路径都不能写开头的斜杠。 主题对它们调用 absURL，写了斜杠会指向域名根目录，丢掉 /{{ $slug }}/ 前缀直接 404。
