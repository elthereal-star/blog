不知道朋友们有没有过这种体验：用 Claude Code 用得正顺手，脑子里突然冒出一个念头——"这玩意儿要是在执行删除命令之前先问我一句就好了"。

今天咱就来盘一盘这个 Mods 到底是个啥玩意儿，怎么写一个自己的，以及——为什么我劝你先看清楚它有多危险。

## Mods 到底是个啥？

用一句话概括：**Mods 是跑在插件里的 JavaScript 或 TypeScript 函数，挂到 Claude Code 自己的事件上，能在事件发生的瞬间插手。**

打个比方哈。Claude Code 干活的时候，其实一直在"喊话"：我要调用一个工具啦、我要弹个权限确认框啦、我要把这一行画面画出来啦……每喊一声，就是一个事件。

Mods 就是站在旁边的一排人。每声喊话传过去，站在最前面的那个人都能做三件事：

- **放行**：听见了，啥也不干，往后传
- **改写**：把喊的内容改一改再往后传（比如把 prompt 里手机号糊成星号）
- **接管**：直接把人拽走，自己处理完，后面的都别管了

多个 Mod 会排成一队，按加载顺序依次过手。第一个加载的最先看到事件、最后拿到结果——所以想搞审计日志的，就得抢在第一个加载，这样别人干的事你全能记下来。

具体能干哪些事，官方文档列得很清楚：

| 能力 | 说明 |
| --- | --- |
| 改写 prompt | 在请求到达模型之前把它换掉 |
| 拦截工具调用 | 拦住、改写，或者让它重试 |
| 批准 / 拒绝权限请求 | 在问你之前，先替你做决定 |
| 给工具输出脱敏 | 密钥之类的东西先擦掉，再让 Claude 读 |
| 画界面 | 在对话旁边开个面板，或者 prompt 上方加一条横幅，能放标签页、按钮、输入框 |
| 重绘原有界面 | 连 Claude Code 自己画的那部分都能改，比如工具调用那一行、转圈动画 |
| 加 `/` 命令 | 敲一下就执行你的函数，不走模型的回合 |

最后一条其实挺关键的。这意味着你可以在 Claude Code 里加一个自己的斜杠命令，而且**不消耗任何 token**——因为压根没跟模型说话。

## 手搓一个最小的 Mod：就三个文件

咱直接上手。一个能跑的最小 Mod，目录长这样：

```text
my-mod/
├── .claude-plugin/
│   └── plugin.json      # 插件声明：这个插件叫啥
└── hooks/
    ├── hooks.json       # 声明我要监听哪些事件
    └── register.js      # 真正干活的代码
```

`register.js` 里就是官方那份示例——数一数 Claude 调了多少次工具，然后把数字显示在转圈动画旁边：

```javascript
let calls = 0

export function register(on) {
  // ① 每次工具被调用时触发
  on('tool.call', async ($, e, next) => {
    calls += 1
    $.ui.invalidate('ui.render')   // 告诉界面：重画一下
    return next(e)                  // 放行，交给下一个 Mod
  })

  // ② 每当界面要画转圈动画时触发
  on('ui.render', { component: 'Spinner' }, async ($, e, next) => {
    return next({
      ...e,
      props: { ...e.props, suffix: ' · tool calls: ' + calls + '…' }
    })
  })
}
```

就这么几行，效果是 `Thinking · tool calls: 3…` 会实时跟着数字跳。

逐个说下这里面的四个东西：

**`on(事件名, 处理器)`** —— 注册一个监听。第二个参数还能再传一个匹配条件，比如上面那个 `{ component: 'Spinner' }`，意思是"只关心界面画转圈动画这一个事件"，别的别来烦我。

**`$`** —— 上下文对象，用来自查和驱动界面，比如 `$.ui.invalidate()` 就是通知某块界面该重画了。

**`e`** —— 事件本身，一个普通对象。你想改什么就改什么，因为它就是一个可以展开重写的字面量。

**`next(e)`** —— **这是整段代码里最重要的一行**。它是"放行"的意思：把（可能被你改过的）`e` 交给下一个 Mod。记住了，**只要你调了 `next`，你就只是个中间商**；哪天你不调了，你就是那个接管的人。

写完三个文件，装上去就行：

```bash
# 在 Claude Code 会话里
/plugin install my-mod@your-org

# 或者在 shell 里
claude plugin install my-mod@your-org
```

从 shell 装的时候如果会话开着，记得敲一句 `/reload-plugins` 让它加载进当前会话。版本要求是 **v2.1.287 以上**，默认就是开着的，不用额外开什么开关。

## 从"能看见"到"能管事"

说实话，数工具调用次数这个例子，只能算"看见"——它没改变任何行为。

真正有意思的是**拦**。

{{< svg "claude-mods" "一个事件穿过 Mod 链的过程：放行、改写、接管" >}}

上面那张图里的三种处理方式，落到实际场景里就是完全不同的东西：

**改写型**——用户提问里写了公司内部域名，Mod 在 prompt 到达模型之前先替换成占位符；或者反过来，在 prompt 末尾自动补一句"这个项目用的是 Java 21 和 Spring Boot 3"，省得每次都要手打一遍。

**接管型**——检测到是对生产环境的配置文件的写操作，不调 `next` 了，直接弹个确认框要求二次确认；或者在 CI/CD 场景下，把流水线的状态拉过来画在对话旁边，构建失败就变红。

**脱敏型**——工具输出里扫到形如 `sk-` 开头的字符串，先糊掉再让模型读。这个在跑 `env`、`cat .env` 这类命令的时候特别有用。

这里我要说句实在话：**上面这些只是设计思路，具体到"某个事件具体怎么拦"，你得去翻官方文档**，事件名和参数形状每个版本都在变，我在这儿编一套 API 给你是害你。文档地址是 `code.claude.com/docs/en/plugins/mods`。

## 最妙的一手，其实是官方自己也用同一套积木

这才是整件事里我觉得最有意思的地方。

Claude Code 里那个 `/diff` 变更面板，**现在已经不是一个写死在产品里的功能了，它就是一个 mod**。你可以在 `/plugin` 里把它关掉，也可以自己写一个替换掉它。官方的意思很明白：以后会有越来越多内置功能被挪到 mods 上去，让核心保持很小，你想要什么自己加回来。

另外两个内置 mod 是 `cc-plugin-agents-md`（负责加载 `AGENTS.md`）和 `cc-plugin-telemetry`。

还有第一个官方出的 Mod 叫 **You Should Know**，它会另起一个 agent 盯着主对话的输出，发现你可能漏掉的重要信息就提醒你一句：

```bash
/plugin enable cc-plugin-you-should-know@builtin
```

**官方团队和外面的开发者，用的是同一套 API，没有特权通道。** 这件事的意义比 Mods 这个功能本身大得多——它意味着"等官方更新"这件事正在被打破，你想要的功能，可能官方还没来得及做，社区已经做完了。

## 但是……先泼一盆冷水

好话说完，说危险的部分。**这段请务必看完再动手。**

官方文档写得很直白：**Mod 运行时的权限和 Claude Code 本身完全一样，而且不做沙箱隔离。** 加载之后，它能干这些事：

- 在你的账户权限范围内任意读写文件、启动程序、发网络请求
- 读你的密钥——包括环境变量和配置文件里的 API key
- 看见你发的每一条 prompt、Claude 做的每一次工具调用
- 改写 prompt 和工具调用，甚至**替你把权限请求批准了**（也就是说，本来会拦下来问你的操作，它可以直接放行）
- 用你套餐或 API key 的额度去调模型

啥意思呢？**装一个来路不明的 Mod，约等于给了对方一个你电脑的 shell。**

这不是我危言耸听。就在 Mods 上线的同一周，Claude Code 发了 **2.1.288**，修了一个漏洞：用 `bash -c` 或者 `sh -c` 包一层的危险删除命令，能绕过原有的防护。更刺激的是，当时 npm 上的 stable 还指着 **2.1.285**——也就是说有一批人以为自己是稳的，其实还暴露着。

所以下面这几条，建议一条不落：

- **只装你信得过的作者和市场上的 Mod。** 和装任何软件一个道理
- 装之前跑一遍 **`claude plugin validate`**，它会把这个插件监听了哪些事件、要求 Claude Code 干什么列出来。看不懂就先别装
- 想彻底关掉：启动时加 **`--safe-mode`**，或者在 `~/.claude/settings.json` 里设 **`"disableAllHooks": true`**
- Team 和 Enterprise 套餐有个内置的 **`sec-default`** Mod，会第一个加载，专门拦着用户装的 Mod 别乱来（比如偷偷覆盖你的权限拒绝规则）。管理员也可以把自己的 Mod 排在它前面
- 顺手把 Claude Code 升级到最新版。这事别拖

说白了，这东西和当年手机刷机装第三方 ROM 是一个性质——**自由是真的自由，代价也是真的代价**。

## 想自己试试？

门槛比想象中低。两条路：

**第一条，让 Claude 自己写。** 直接在会话里描述你想要什么功能，它会用内置的 `plugin-authoring` 技能把 TypeScript 写出来、装上、热重载。也就是说，你可以用 Claude Code 来改 Claude Code（套娃警告）。

**第二条，自己动手。** 就是上面那三个文件，从官方的示例仓库抄一份改改最快。

对了，补一个细节：Mods 在 CLI 和桌面版的 Code 标签页里能完整跑，包括画界面那部分；VS Code 扩展的聊天面板和 `claude -p` 模式下**只会执行 hooks，不会画 Mod 的界面**。如果你写的 Mod 主要靠面板显示东西，别在 VS Code 里试半天找不着，容易怀疑人生。

Windows 上装的兄弟，命令基本一样，就是注意别把路径写成 `C:\xxx\yyy` 那种反斜杠——JSON 里得转义，建议全用正斜杠。

## 写在最后

回过头看，Anthropic 这波操作挺聪明的：9 月下旬上线 Claude Marketplace 和付费开发者提交门户，打通了上传、校验、安全扫描、人工审核一整条上架流程；10 月 1 号紧接着放出 Mods，把"深度改装"的口子也开了。**十几天时间，应用商店、上架审核、开发者后台、深度改装能力，四块拼图全齐了。**

以前这种扩展能力只有一个归宿：等官方版本更新。现在这道墙被拆了。

但我也得说句公道话——把这么强的权限交给一个不做沙箱的插件系统，风险是实打实的。社区现在正是最狂热的时候，什么好玩的都往里塞，这时候最容易忽略"这个 Mod 到底读了我什么"。**玩归玩，别拿生产环境当试验田。**

对我个人来说，最有意思的其实是那个宝可梦的例子。作者自己说，整个 mod 是让 Opus 5.5 写完的。也就是说，**工具在改造自己**——这件事的开头可能比 Mods 这个功能本身重要得多。
