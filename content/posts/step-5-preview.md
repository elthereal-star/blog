## 先用一句大白话给它定性

**Step 5 Preview 是一个"家里挂着 6000 亿参数编制、每次只叫醒 270 亿干活"的大模型。**

翻译成人话：能力按大模型算，账单按"小模型"算。官方管这个叫"拓展帕累托边界"——同样的钱能买到更多智能，同样的智能能少花钱。这买卖怎么看怎么划算，所以发布还没满月，它先是上了 OpenRouter，接着在 10 月 10 号直接登顶了人家的 Trending 榜。

> 帕累托边界：智能和成本之间那条"想多吃多占就得加钱"的线。谁能把这条线往外顶，谁就是真进步。

## 啥是稀疏 MoE？600 人的公司为啥只叫 27 个人干活

要搞懂它为什么便宜，得先搞懂 **MoE（Mixture of Experts，混合专家）** 这玩意儿。

传统的稠密模型是什么样呢？一个 token 进来，从第一层到最后一层，所有参数全都得起来加班。7B 的模型就是 7B 全员上阵，671B 的模型就是 671B 全员上阵——参数量越大，每次前向传播越贵，而且一分钱都省不下来。

MoE 的思路就骚气了：**把参数切成一大堆"专家"，每次只挑几个相关的干活。**

打个比方啊。稠密模型是那种 600 人的小工厂，来个订单全厂停工停产一起上手，甭管这订单是拧螺丝还是写标书；MoE 是另一种 600 人的公司，但内部早就分好了工种——订单先过一个 **router（路由器，你就理解为派活的主管）**，主管看一眼活儿的内容：哦，财务的，那叫醒财务部那几个人，其他人该摸鱼摸鱼。而计算量呢，只按出勤的人发。

所以 Step 5 Preview 敢说自己是"600B 模型"：6000 亿参数是它的**总编制**，决定了能力的天花板；每个 token 实际只激活 270 亿，决定了**每次干活的实际开销**。家里挂着 600 人的编制，发工资只按出勤的 27 人发——这不就是咱们打工人的终极梦想吗 ( ᖛ ̫ ᖛ )

{{< svg "step5-moe" >}}

诶对了，多一句嘴：MoE 这个思路本身不新，DeepSeek、Qwen、Kimi 都在玩。但 Step 5 Preview 把"总参数 / 激活参数"这个比例拉到了 22:1（600B 对 27B），确实算是比较激进的。比例拉得越开，省钱是越省钱，可"派活的主管"一旦看走了眼，该醒的人没醒，活儿就得干砸——所以它才要在 router 相关的组件上专门做优化，这个后面会讲。

## 架构上它到底还抠了哪些细节

光有个 MoE 架子不稀奇，真正决定体验的是细节。官方技术报告里点了这么几件事，咱一个个翻译成大白话：

| 招式 | 官方说法 | 通俗版 |
| --- | --- | --- |
| 窄而深 | 92 层 Transformer，单层更窄 | 不养 3 个全科大佬，改招 92 个专科大夫，一层治一种病 |
| Sparse GQA | 稀疏分组查询注意力 | 开会不用人人做会议纪要，一个组派一个记录员，KV cache 直接瘦身 |
| Block-wise Token Merging | 分块合并 token | 把 router 里最贵的 Indexer 和 Top-k 选择成本砍掉 8 倍 |
| Long-horizon RL | 长程强化学习 | 专门训练"执行—反馈—修正"的长任务，不是一问一答的乖学生 |
| Context Compaction | 上下文压缩 | 活儿干太长了自动做小结，别把 1M 的窗口撑爆 |

里面我最感兴趣的是 **Block-wise Token Merging**。为啥？因为 MoE 有个隐形成本大伙儿平时不提：token 越多，router 要做选择的开销越大，长上下文场景下这玩意儿能吃掉一大块性能。它这个方案直接把 Indexer 和 Top-k 选择这两块的成本降了 8 倍——1M 上下文才真正从"参数表上的数字"变成"用得起的数字"。

还有 **Context Compaction** 也挺实在。1M 上下文听着爽，可你真扔个 80 万字的代码库进去，先不说钱，模型自己看着看着就跑偏了。边跑边自动小结，相当于给模型配了个记笔记的助手，这谁不爱呢 (￣▽￣)~*

## 两个长程实验，这个确实有点东西

要说这场发布会里最让我坐直身体的，是官方放的两个"长任务"实验。前面那些 benchmark 考的是一问一答，这俩考的是**让 AI 熬一个通宵干活**。

**实验一：24 小时的 GPU Kernel 优化。** 任务甩给模型：优化 GPU 上跑矩阵乘法的 kernel，目标是把性能榨上去。这活儿没有标准答案，得靠"改一版→跑一跑→看数据→再改"的循环反复搓。循环搓了 24 小时之后，它交出的方案，MLA 峰值跑到 **508 TFLOPS**——同一份报告里，Claude Opus 5 的数字是 493。

**实验二：让它调教另一个模型。** 用自动化的后训练流程，把 Qwen3-30B-A3B 在 AIME24（美国数学邀请赛）上的成绩从 53.3% 刷到了 **60%**。

还有个花活：官方让它改一块 ESP32 开发板，连续执行了 3 个多小时没跑偏。

这几个实验说明的是同一件事——**它是在往"长程智能体"这个方向使劲的。** Agent 任务的本质不是答题，是"执行、反馈、修正"的循环，考验的是不跑偏、不忘事儿、不半路开溜。而"70% 专家认为能自主解决中等偏复杂编程任务"，说的也是这个能力。当然咯，3 小时跟 24 小时之间还差着一整个阶级，但方向是对的。

## 想现在就想上手？代码给你

OpenAI 兼容，改个 base_url 就能用，三行代码的事儿：

```python
from openai import OpenAI

# 阶跃星辰的 API 完全兼容 OpenAI SDK，换 base_url 和模型名就行
client = OpenAI(
    api_key="YOUR_STEP_API_KEY",           # 去 platform.stepfun.com 注册，自己来一把
    base_url="https://api.stepfun.com/v1",
)

# 注意 reasoning_effort 这个参数：low/medium/high 三档
# 简单活儿用 low 省钱，硬骨头再上 high，别一上来就拉满
resp = client.chat.completions.create(
    model="step-5-preview",
    messages=[{"role": "user", "content": "帮我把这个函数的复杂度从 O(n²) 降到 O(n log n)"}],
    reasoning_effort="medium",
    stream=True,
)

for chunk in resp:
    # 推理模型的"思考过程"在 delta.reasoning 里，正文在 delta.content
    if getattr(chunk.choices[0].delta, "reasoning", None):
        print(chunk.choices[0].delta.reasoning, end="", flush=True)
    elif chunk.choices[0].delta.content:
        print(chunk.choices[0].delta.content, end="", flush=True)
```

不想写代码的，它家开放平台有个 Studio，可以直接在浏览器里搓模型；另外还有个 Step Plan 订阅服务，页面上写着限时免费，内置多模型智能路由，适合懒得接 API 的朋友。

哦对了，还有一条白嫖路线：OpenRouter 上它也挂着，10 月 8 号上的架，10 月 10 号登顶过 Trending。按 token 付费，没有订阅捆绑，适合先花几美分试试水，再决定要不要深度绑定。
