## 咱先唠唠，内网穿透到底是个啥？

在动手整活之前，先把概念搞明白，不然连自己在干嘛都不知道那可太尴尬了。

### 用大白话说

想象一下你在宿舍里开了一家"小黑店"（你本地的 Web 服务），但问题来了——你的宿舍在一栋没有门牌号的大楼里（内网），外面的人想找你买东西，根本不知道你在哪栋楼、几层、几号房间。

那咋办呢？你在校门口（公网服务器）租了一个**代收点**，在校门口放一个牌子："想找小黑店的人，来校门口这个摊位，我帮你转交"。

外面的顾客只需要去校门口的代收点，代收点就会把他们的请求转交给你，然后把你的回应再转交给顾客。

**这个"代收点"就是内网穿透的核心**——通过一台有公网 IP 的服务器做中转，让外网用户能访问到你内网的服务。

{{< svg "nat-traversal" >}}

### 稍微专业一点说

咱家里或公司的电脑，一般分配的都是**内网 IP**（比如 192.168.x.x、10.x.x.x），这些 IP 只能在局域网里用，互联网上的人是访问不到的。只有路由器或光猫拥有的那个**公网 IP**，才能被互联网访问。

但问题是，很多运营商（尤其是移动、联通、电信的家宽）压根不给你独立公网 IP，或者给了也是"假公网"（NAT4444 了解一下），你就算在路由器上做了端口映射，外面照样访问不了。

**内网穿透（NAT Traversal）**，就是绕过这些 NAT 限制，让外网设备能够直连或间接到你内网的服务。

## 啥时候你需要内网穿透？

先列几个典型场景，看看你是不是这些情况：

- **本地开发调试，想给客户/老板看效果**：总不能让他们来你工位上看吧？
- **微信/支付宝支付回调**：这些第三方服务需要回调你的服务器，你本地跑的项目得有个公网地址才行
- **家里搭了个 NAS/树莓派**：出门在外想访问家里的文件和服务
- **联机打游戏**：Minecraft、泰拉瑞亚啥的，自己开服让基友连进来
- **异地办公访问公司内网**：公司没搞 VPN，你又需要连回去

如果你中了两条以上，恭喜你，内网穿透就是你需要的 (｡･ω･｡)

## 主流的内网穿透方案，咱一个一个看

目前市面上主流的方案大概有这么几种，每种都有自己的脾气，咱来逐个瞅瞅：

### 1. frp（Fast Reverse Proxy）—— 自部署的首选

**frp** 是目前最流行的开源内网穿透工具，由 GitHub 上的 fatedier 大佬维护，Star 数库库地往上涨。

**原理很简单**：你在一台有公网 IP 的服务器上跑 `frps`（服务端），在你本地跑 `frpc`（客户端），客户端主动连上服务端，建立一条隧道。外网请求打到服务端，服务端通过隧道转发给你本地的客户端。


**优点**：
- 完全开源免费，GitHub 上一搜就有
- 性能猛猛的，毕竟是 Go 写的
- 支持 TCP、UDP、HTTP、HTTPS、STCP 等各种协议
- 配置简单，一个 .toml 文件搞定
- 可以自己控制一切，数据走自己的服务器

**缺点**：
- 你得有一台**有公网 IP 的服务器**（阿里云、腾讯云这种）
- 带宽受限于你服务器的带宽，服务器买的 1M 小水管就慢慢传吧

### 2. ngrok —— 懒人首选

**ngrok** 是最早火起来的内网穿透工具，人家帮你把服务端都搭好了，你只需要下载个客户端，一行命令就能把本地端口暴露出去。

```bash
ngrok http 8080
```

就这么简单，回车之后你会得到一个类似 `https://xxxx.ngrok.io` 的公网地址，直接发给别人就能访问了。

**优点**：
- 零配置，开箱即用
- 自带 HTTPS 证书，不用自己折腾
- 有 Web 界面可以查看请求详情，调试神器

**缺点**：
- 免费版域名随机生成，每次重启都变（这个比较鸡贼啊）
- 免费版有带宽和连接数限制
- 数据经过 ngrok 的服务器，敏感项目别用
- 国内访问速度看缘分，毕竟服务器在国外

### 3. Cpolar —— 国内玩家的福音

如果你觉得 ngrok 是好东西但连国外太慢了，那你一定要认识一下 **Cpolar**。这玩意儿说白了就是 **ngrok 的国内平替**，功能几乎一样，但服务器在国内，速度库库快，而且有全中文的 Web UI 管理面板。

很多学 Java 的朋友（比如黑马程序员那条路线）应该在苍穹外卖之类的课程里见过它，一行命令就能把你的本地项目暴露到公网，讲师不用在课堂上折腾服务器安全组，学生也不用去买云服务器，皆大欢喜。

```bash
cpolar http 8080
```

回车之后你会得到一个类似 `https://xxxx.cpolar.cn` 的公网地址，直接就能用。


**Cpolar 的 Web UI 长这样**：浏览器打开 `http://localhost:9200` 就能进入管理面板，在这里你可以看到所有隧道的状态、流量统计、请求日志，还可以在图形界面里改配置，完全不用手写配置文件，对新手极其友好。

**优点**：
- 服务器在国内，访问速度比 ngrok 快得多，不用跨洋
- 全中文 Web UI 管理面板，可视化管理隧道，不用记命令行
- 免费版给固定二级域名，不会每次重启换地址（这点比 ngrok 良心！）
- 支持 HTTP、HTTPS、TCP 等多种协议
- 国内支付方便，微信支付宝直接搞定

**缺点**：
- 免费版有带宽和流量限制，高并发就别想了
- 数据走 Cpolar 的服务器，敏感项目还是别用
- 需要注册账号才能用，不像 ngrok 能匿名直接跑（不过注册也免费）

### 4. Cloudflare Tunnel（原 Argo Tunnel）—— CDN 加持的大杀器

如果你的域名托管在 Cloudflare，那这个方案简直不要太香。

**核心优势**：它不仅帮你穿透，还把流量接入了 Cloudflare 的全球 CDN 网络，自动帮你抗 DDoS、加速静态资源、还自带免费 SSL 证书。

```bash
cloudflared tunnel --url http://localhost:8080
```

**优点**：
- 免费，不需要自己买服务器
- Cloudflare 全球 CDN 加速
- 自带 DDoS 防护和 HTTPS
- 域名可以固定（需要绑自己的域名到 Cloudflare）

**缺点**：
- 需要域名托管在 Cloudflare
- 在国内部分区域访问可能被 QOS
- 只支持 HTTP 协议（TCP/UDP 玩不了）

### 5. ZeroTier / Tailscale —— 组建虚拟局域网

这俩跟上面的方案思路不一样——它们不是把你暴露到公网，而是把多台设备**组进一个虚拟局域网**。

装了 ZeroTier 之后，你在星巴克喝咖啡，跟家里的 NAS、公司的电脑，都在同一个虚拟网络里，互相可以直接用虚拟 IP 访问，就像连了同一台路由器一样。


**优点**：
- Peer-to-Peer 直连，不经过中转服务器（快！）
- 适合长期使用，一旦组好网就一直能互通
- 安全性高，只有加入你网络的人才能访问

**缺点**：
- 所有要互联的设备都得装客户端
- 想给外人访问就不太方便了（总不能让人家也装一个吧）
- 部分网络环境下 P2P 打洞会失败，变成中转模式会变慢

## 咱来实操作业：用 frp 整一个内网穿透

好了，概念咱都搞明白了。现在咱挑一个最经典、最灵活的方案——**frp**，手把手带大家整一遍。

**咱的场景假设**：你在阿里云有一台最低配的服务器（有公网 IP），想把你本地电脑 8080 端口上跑的 SpringBoot 项目暴露出去。

### 第一步：服务器上装 frps

SSH 连上你的云服务器，先下载 frp：

```bash
# 咱先看看最新版本是多少 → https://github.com/fatedier/frp/releases
# 目前最新是 0.61.x，这里以 0.61.1 为例
wget https://github.com/fatedier/frp/releases/download/v0.61.1/frp_0.61.1_linux_amd64.tar.gz

# 解压
tar -zxvf frp_0.61.1_linux_amd64.tar.gz

# 进去看看里面有啥
cd frp_0.61.1_linux_amd64
ls
```

你会看到一堆文件，咱只关心两个：
- `frps` —— 服务端程序
- `frps.toml` —— 服务端配置文件

**注意，如果你用的版本还叫 `frps.ini`，说明版本比较老，新版本的 frp 已经全面迁移到 toml 格式了。**

编辑服务端配置：

```toml
# frps.toml
# frp 服务端监听端口，客户端会连这个端口
bindPort = 7000

# 服务端 Dashboard 管理界面
# 浏览器访问 http://你的服务器IP:7500 就能看到
webServer.addr = "0.0.0.0"
webServer.port = 7500
webServer.user = "admin"
webServer.password = "admin123"  # 记得改掉，别真用 admin123！

# Token，客户端连过来的时候要对得上
auth.token = "ni-men-yao-xue-hui-zi-ji-gai-token-a"
```

配置写好之后，启动它：

```bash
# 直接前台运行（先确认没报错）
./frps -c frps.toml

# 确认没问题的话，后台运行
nohup ./frps -c frps.toml > /dev/null 2>&1 &
```

如果控制台打印 `frps started successfully`，恭喜你，服务端已经跑起来了！

**这里有个坑提醒一下**：记得去你云服务器的**安全组/防火墙**里放行 `7000` 和 `7500` 端口，不然客户端连不上，Dashboard 也访问不了。阿里云、腾讯云默认只开了 22 和 80，其他的都得手动加。

### 第二步：本地电脑装 frpc

假设你是 Windows 系统，同样去 [frp Releases 页面](https://github.com/fatedier/frp/releases) 下载 `frp_0.61.1_windows_amd64.zip`，解压到你喜欢的地方。

编辑 `frpc.toml`：

```toml
# frpc.toml
# 连到你的服务器
serverAddr = "你的云服务器公网IP"  # 比如 1.2.3.4
serverPort = 7000

# 这个 token 必须跟服务端的一样
auth.token = "ni-men-yao-xue-hui-zi-ji-gai-token-a"

# 咱要暴露的本地服务
[[proxies]]
name = "my-cool-project"        # 代理名称，随便起
type = "tcp"                     # TCP 协议
localIP = "127.0.0.1"           # 本地服务 IP
localPort = 8080                 # 本地服务端口
remotePort = 8080                # 在服务器上监听的端口，外网用户通过这个端口访问
```

然后在 frp 目录下打开命令行（在文件夹地址栏直接敲 `cmd` 回车就行），运行：

```bash
frpc.exe -c frpc.toml
```

看到 `[proxy] [my-cool-project] start proxy success` 就说明隧道建立成功了！

### 第三步：验证一下

打开浏览器，访问 `http://你的服务器公网IP:8080`，如果能打开你本地的项目——那就说明成功啦！

打开 Dashboard 看一眼：`http://你的服务器公网IP:7500`，用刚才设置的用户名密码登录，你会看到连接状态、流量统计等等，一目了然。


### 如果要暴露的是 Web 服务，再加一步：配置子域名

刚才那种 TCP 方式，得记住端口号，给朋友分享还要解释"冒号8080"是啥意思。我们可以用 HTTP 代理 + 域名，让访问更优雅。

首先，你得有一个域名，并且把域名解析到你的服务器 IP。假设你的域名是 `example.com`。

服务端 `frps.toml` 加一段：

```toml
# 服务端额外配置
vhostHTTPPort = 80  # HTTP 虚拟主机端口，直接用 80
```

客户端 `frpc.toml` 改成：

```toml
[[proxies]]
name = "my-cool-project"
type = "http"                    # 这次用 HTTP 代理
localIP = "127.0.0.1"
localPort = 8080
customDomains = ["project.example.com"]  # 用你自己的子域名
```

重启两端后，访问 `http://project.example.com` 就能直接到你的本地项目了，不用加端口号，nice！

## 各方案怎么选？一张表看完

| 方案 | 适合谁 | 需要啥 | 缺点 |
|------|--------|--------|------|
| **frp** | 有一台云服务器，想完全掌控 | 云服务器 + 一点点动手能力 | 要自己维护服务器 |
| **ngrok** | 临时调试，懒得注册账号 | 啥都不用准备 | 免费版地址每次变，服务器在海外慢 |
| **Cpolar** | 国内新手，想要可视化操作 | 注册个免费账号就行 | 免费版有流量限制，数据走第三方服务器 |
| **Cloudflare Tunnel** | 域名在 Cloudflare，做网站 | Cloudflare 账号 | 不支持 TCP/UDP |
| **ZeroTier/Tailscale** | 多设备互联，长期用 | 每台设备装客户端 | 不适合给外人访问 |

**咱的建议**：
- 偶尔调试 + 人在国内 → **Cpolar**，中文面板 + 国内服务器，对新手最友好
- 偶尔调试 + 懒得注册 → **ngrok**，匿名直接跑，但国内慢
- 有服务器就上 **frp**，自己掌控一切
- 域名在 Cloudflare 且只暴露 HTTP 服务，**Cloudflare Tunnel** 是绝配
- 自家设备组网用 **ZeroTier**，装一次爽一辈子

如果有朋友觉得 frp 配置还是有点麻烦，那强烈建议先从 **Cpolar** 上手（苍穹外卖同款，懂的都懂），体验一下内网穿透是个什么感觉，注册个账号打开 Web UI 点点点就完事了，之后再慢慢折腾 frp 也不迟。

## 补充几个容易踩的坑

1. **服务器防火墙/安全组没放行**：这是新手最容易犯的错误，frp 所有用到的端口（bindPort、remotePort、Dashboard 端口）都要在安全组里放行，不然咋折腾都不通。

2. **Token 两端不一致**：服务端和客户端的 `auth.token` 必须完全一样，差个空格都不行。如果客户端连不上报 auth error，先检查这个。

3. **80 和 443 端口被占用**：如果你想把 frp 的 vhostHTTPPort 设成 80，但服务器上已经装了 nginx 也在用 80，就会冲突。要么关掉 nginx，要么换个端口。

4. **国内服务器备案问题**：如果你在国内服务器上用 80/443 端口做 HTTP 穿透，域名是需要备案的，不然会被运营商拦截。建议用非标准端口（比如 8080、8443）绕过备案限制，或者直接用海外服务器。

5. **带宽瓶颈**：frp 所有流量都经过你的云服务器，你服务器买的是 1Mbps 小水管，那访问速度也最多 1Mbps（大概 128KB/s），加载个大图片都得等半天。这个没办法，加钱升级吧  (￣▽￣)~*

6. **安全性**：暴露到公网意味着全世界都能扫到你的服务，**一定要**给服务加上认证（登录密码、Token 等），别裸奔。frp 的 Dashboard 密码也记得改成强密码，别用默认的。

## 收尾总结

内网穿透这东西，本质上就是想办法让"里面的人"和"外面的人"能对上话。方式有好多种，简单粗暴的 Cpolar/ngrok 一行命令完事，自由度高的 frp 想咋折腾咋折腾，想组网的 ZeroTier 默默干活。选择哪个，取决于你的实际场景和手里有啥资源。

我们最常用的组合是：**临时调试用 Cpolar（国内）/ ngrok（海外），长期服务用 frp，自家设备用 ZeroTier**，各司其职，一点都不冲突。
